# v0.x: an MCP edit fails when a `cmd.go` was kept

`gtb enable mcp <path>`, `gtb disable mcp <path>` and `gtb annotate` used to report success when they kept a command's
`cmd.go`, because it was edited by hand or `.gtb/ignore` covers it. The manifest changed and the built tool did not, so
a command could stay on the MCP surface after a run that said it was withheld.

## What changes

- The run exits non-zero, and one warning per kept command gives the command that applies the change. The other
  commands in the same call are still done.
- A path on the withhold list fails the same way while `.gtb/ignore` covers a root `cmd.go` that does not carry it.
- All three commands take `--overwrite ask|allow|deny`.
- `RunMCPCommand` in `cli/pkg/cmd` takes the overwrite mode after the project path.

## What to do

- In a script that edits a hand-edited command, add `--overwrite allow` to replace the file.
- For a file in `.gtb/ignore`, take it out with `gtb ignore remove <file>` and run the command again.
- If you keep the file and carry the call in it yourself, expect the non-zero exit: gtb does not read the call back.
