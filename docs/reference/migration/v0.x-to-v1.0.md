# Migrating from v0.x to v1.0

This guide covers every breaking change accumulated during the v0.x development
cycle. Changes are grouped by package. Each entry states what changed, shows
before/after code, and provides a migration path.

---

## Breaking Changes

### Logger boundary: `logger.Logger` mirrors `*slog.Logger`

**Packages affected:** `pkg/logger`, `pkg/props`, and every package with a
logging seam (`pkg/config`, `pkg/controls`, `pkg/errorhandling`, `pkg/http`,
`pkg/grpc`, `pkg/gateway`, `pkg/telemetry`, …)

`pkg/logger.Logger` is now an interface that mirrors the standard library's
`*slog.Logger` method set exactly, a `*slog.Logger` satisfies it directly and
can be assigned to `props.Props.Logger`. The format-string helpers (`Infof` …),
`Fatal`, `Print`, `WithPrefix`, and the `SetLevel`/`GetLevel`/`SetFormatter`
interface methods were removed. Reusable **constructors now take a
`*slog.Logger`**; wrap an application `logger.Logger` with `logger.ToSlog(...)`
at the call site.

**Before / After:**

```go
// before — a logger.Logger passed directly
handler := errorhandling.New(props.Logger, nil)
controller := controls.NewController(ctx, controls.WithLogger(props.Logger))

// after — wrap at the boundary (ToSlog is nil-safe)
handler := errorhandling.New(logger.ToSlog(props.Logger), nil)
controller := controls.NewController(ctx, controls.WithLogger(logger.ToSlog(props.Logger)))
```

See [Logger slog-first boundary](v0.x-logger-slog-first.md) for the full
removed-method mapping and the list of affected constructors.

---

### Config factories use functional options and a `*slog.Logger`

**Package:** `pkg/config`

Container factories take an `afero.Fs` plus functional options; the logger
option now takes a `*slog.Logger`:

```go
container := config.NewFilesContainer(fs,
    config.WithLogger(logger.ToSlog(appLog)),
    config.WithConfigFiles(paths...),
)
```

Reusable packages no longer read `config.Containable` inside their cores, they
own typed settings structs, and GTB reads config through `*FromContainable`
adapters. See [Typed config section adapters](v0.x-config-section-adapters.md).

---

### gRPC server: `server.grpc.reflection` config key required

**Package:** `pkg/grpc`

The gRPC server now checks `server.grpc.reflection` (bool) to conditionally
enable server reflection. This key did not exist in v0.x, which caused the
server to always register reflection.

**Before:** No config key. Reflection was always enabled.

**After:**

```yaml
# config.yaml
server:
  grpc:
    reflection: true   # set to false to disable reflection in production
```

**Migration:** Add `server.grpc.reflection: true` to your embedded default
config (or runtime config file) to preserve the previous behaviour. Set to
`false` in production environments where reflection should be disabled for
security reasons.

---

### gRPC server port: `server.grpc.port` takes precedence

**Package:** `pkg/grpc`

Port resolution now checks `server.grpc.port` first, falling back to
`server.port` if not set. In v0.x only `server.port` was consulted.

**Before:**

```yaml
server:
  port: 9090
```

**After (recommended):**

```yaml
server:
  grpc:
    port: 9090
```

**Migration:** Add `server.grpc.port` to your config. The old `server.port` key
still works as a fallback, so this is not strictly required unless you are
running both HTTP and gRPC servers on different ports.

---

### HTTP server relocated: `pkg/http`

**Package:** `pkg/http` (previously `pkg/server/http`)

The HTTP server factory was moved to its own top-level package.

**Before:**

```go
import "gitlab.com/phpboyscout/go-tool-base/pkg/server/http"
```

**After:**

```go
import "gitlab.com/phpboyscout/go-tool-base/pkg/http"
```

**Migration:** Update import paths.

### `controls.Controllable` interface narrowed

**Package:** `pkg/controls`

The `Controllable` interface was split into four role-based interfaces:
`Runner`, `StateAccessor`, `Configurable`, and `ChannelProvider`. The full
`Controllable` interface still exists as a composition of all four, but
`ControllerOpt` functions now accept `Configurable` rather than `Controllable`.

**Before:**

```go
func MyOption(c controls.Controllable) {
    c.SetLogger(l)
}
```

**After:**

```go
func MyOption(c controls.Configurable) {
    c.SetLogger(l)
}
```

**Migration:** Update custom `ControllerOpt` implementations to accept
`controls.Configurable`. If you only use the provided options (e.g.
`WithLogger`, `WithShutdownTimeout`), no changes are required. Note `WithoutSignals` was removed in go/controls v0.2.0. See [controls signals are now opt-in](v0.x-controls-signal-ownership.md).

---

### Error library: `cockroachdb/errors` replaces `go-errors/errors`

**All packages**

All GTB packages now use `github.com/cockroachdb/errors` for error creation and
wrapping. The `go-errors/errors` dependency has been removed.

**Before:**

```go
import "github.com/go-errors/errors"
err := errors.New("something went wrong")
```

**After:**

```go
import "github.com/cockroachdb/errors"
err := errors.New("something went wrong")
```

**Migration:**

1. Replace `github.com/go-errors/errors` with `github.com/cockroachdb/errors`
   in your import paths.
2. `errors.New`, `errors.Wrap`, `errors.Errorf` are API-compatible.
3. `errors.Is` / `errors.As` behave identically.
4. Remove `go-errors/errors` from `go.mod` / `go.sum` after migration.

---

## Deprecations

No APIs are deprecated at v1.0, the deprecations listed in individual v0.x
specs have been fully removed. See the relevant v0.x release notes for details.

---

## New Features in v1.0

- **`pkg/logger`**: Unified logger abstraction with charm/slog/noop backends.
- **`pkg/controls` self-healing**: `WithRestartPolicy` enables automatic
  service restarts with exponential backoff.
- **`pkg/controls` liveness/readiness probes**: `WithLiveness` and
  `WithReadiness` options for Kubernetes-compatible health checks.
- **`pkg/http` hardened client**: `NewSecureClient()` returns a pre-configured
  `*http.Client` with TLS verification, timeout, and redirect limits.
- **`pkg/cmd/root` middleware**: `RegisterPreRunMiddleware` allows packages to
  inject pre-run logic without modifying the root command.
